    Start here — orientation for a cold-start agent¶

    Read this file, then read only what your task needs. The project's records are large on purpose (every claim carries its evidence) and no agent can or should ingest them whole: PROJECT_PLAN.md alone is ≈660 KB, about a full context window. Paging through it costs tokens and, worse, silently misses the paragraph that mattered. Grep for a chunk ID; read the row and the span it points to; stop.

    This file holds no status of its own. The state table lives in the dashboard, the chunk list below is generated from PROJECT_PLAN.md §7, and everything else is a pointer. If something here disagrees with the plan, the plan is right and this file is stale — say so.

    1. What is true right now — one table, maintained daily¶

    docs/status/dashboard.md → "Honest current state" (≈ 15 rows: capability, state, the gate that licenses it, and what is not claimed). It is a digest of PROJECT_PLAN.md §2, rewritten by every daily review. Read it before trusting any S-parameter, coil-loading or SAR figure. For the full wording of a claim, grep its chunk ID in §2.1 (validated, with the number) or §2.2 (not validated — do not trust, do not extend).
