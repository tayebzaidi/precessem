    Step 1: the scratch-repo clause of the Done-when, behind an opt-in key, with the default path byte-identical. Implementer; smoke; no MPI, no container, no compute.

    Why it is queueable now. - The §7 row says "do not queue until a measured window has actually overlapped a slot, or the weekly decides the risk warrants it". The weekly has decided twice: - "OPS-54 — queue it; it is the right use of a drained slot" (plan-archive.md:34768); - "OPS-54 step 1 if assertable in a slot", in the current lane-1 list (PROJECT_PLAN.md §10, "Lane 1 and lane 2, targets for the daily"). - The earlier "the operator's (a compose mount)" (plan-archive.md:35131) is answered by keeping the mount change a default-preserving interpolation.     Construction (additive). - xl-run.sh reads a new queue-entry key, XL_IMMUTABLE_CHECKOUT=1, beside XL_OUTPUTS. Unset leaves today's path untouched. - When the key is set, xl-run.sh: - records the window's start HEAD sha; - runs git worktree add --detach <gitignored path, e.g. .xl-worktree/> <sha>; - exports FEM_EM_XL_WORKSPACE to that path before its existing up -d --force-recreate; - runs the queued command against that view; - after the window, copies the declared XL_OUTPUTS and any in-tree raw-capture files back into the main tree before its existing staging step (xl-run.sh:199–245); - removes the worktree (git worktree remove --force, then git worktree prune). - In docker/docker-compose.yml the xl and xxl services' ..:/workspace becomes ${FEM_EM_XL_WORKSPACE:-..}:/workspace. Edit it with the Edit tool (see traps). - The gitignore entry goes in .gitignore. The scratch test copies that file (test_xl_window_isolation.sh:53).

    1. Anchor (byte identity). In a new window 7 of scripts/testing/test_xl_window_isolation.sh, the queued probe:
    2. reads src.txt in its own view ($PWD under the stub, i.e. the worktree);
    3. commits a change to src.txt on main in $REPO mid-window (a real git commit, not an edit);
    4. re-reads its view.

    Asserted: - the view's sha256 after the concurrent commit equals git show <start-sha>:src.txt's sha256; - main's src.txt does carry the change; - after the window, the worktree path is gone and git worktree list has one entry; - a declared output written inside the view is present in the xl-run commit. 2. Negative control. Window 7′: the same probe and the same concurrent commit with the key unset. Assert that the view's sha256 differs from the start blob, i.e. the live tree moved under the window, which is the defect. This is a planted boolean control, asserted as OPS-64's windows 5–6 are. Rule (e) governs factors, and no factor is claimed. Regression: windows 1–6 stay green unmodified. This is the evidence that the default path is unchanged. 3. Tier, ranks, wall clock.     Review ruling 2026-10-15 18:00 (item 487 — NOT queued)¶

    Declined; the draft above is banked for the operator. It edits docker/docker-compose.yml's volumes: (..:/workspace → ${FEM_EM_XL_WORKSPACE:-..}:/workspace). §9's standing constraint on the compose allow says: "Edit only environment: keys. Do not touch volumes:, do not add a mount, do not widen a path". It also says "A chunk that believes it needs a mount change is a blocked finding for the operator". A default-preserving interpolation still makes the mounted host path settable from the environment, which is a widening. Only the operator can authorize it. The dashboard carries it as the operator's (carried item "OPS-54 is yours (a compose mount)"). Number 487 is spent and is not reused.
