    OPS-57 — S ↔ Z conversions: let the solve report singularity; one impedance-to-S implementation¶

    S ↔ Z conversions: let the solve report singularity; one impedance-to-S implementation — opened 2026-09-19 (interactive session, from an external code review). ports/circuit.py tests singularity with abs(np.linalg.det(m)) == 0.0 at three sites (terminate's I − S_bb Γ at :138, s_to_z at :167, z_to_s at :185). A determinant is scale- and dimension-dependent — 1e-21 · I₁₆ has det == 0.0 exactly and condition number 1 — so the test can reject a perfectly conditioned matrix. Honest size: unreachable on this project's matrices (I − S has O(1) entries, Z + z0 I a diagonal ≥ z0), so this is a correctness-of-intent fix, not a live defect. The real weakness is the opposite one: == 0.0 catches only exactly singular matrices, which np.linalg.solve already refuses (LinAlgError: Singular matrix), so the line is a second factorisation that adds a message and no protection. Separately, ports/sparameters.py::sparameters_from_impedance is the same formula as z_to_s with an explicit np.linalg.inv, a non-finite check z_to_s lacks, and a looser z0 check. Plan. (1) Drop the three determinant tests; wrap each solve in try / except np.linalg.LinAlgError and raise ValueError with the existing message text. (2) Add the non-finite input check to s_to_z / z_to_s. (3) sparameters_from_impedance keeps its signature and docstring and delegates to z_to_s (check the import direction first — no cycle). No conditioning threshold: a near-open-circuit S legitimately has a huge Z, and a cut-off would be an invented tolerance. Done-when (§4): unit tests — round trip z_to_s(s_to_z(S)) to ≤ 1e-12 on a 16-port matrix scaled so its determinant underflows (the pre-change control: the pinned pre-change sha raises on it); an exactly singular I − S still raises ValueError with the same message at all three sites; sparameters_from_impedance and z_to_s agree to ≤ 1e-14 on a random passive Z. Standing rule (c): inv → solve moves S in the last bits, so tests/ports and the PORT validation gates that consume sparameters_from_impedance are re-run at -n 2 and must be green with no tolerance touched — a gate that fails on a last-bit change is a finding about that gate, reported, not loosened.
