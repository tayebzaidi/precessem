    OPS-58 — Private-leak check: commit messages, fail-closed on inspection errors, "skipped" is not "clean", and a positive control¶

    Private-leak check: commit messages, fail-closed on inspection errors, "skipped" is not "clean", and a positive control — opened 2026-09-19 (interactive session, from an external code review, which framed these correctly as limits of the mechanism, not evidence of a leak). (a) CLAUDE.md forbids AED figures in commit messages, but check_private_leak.py runs as pre-commit, which never sees the message. (b) staged_additions() and tracked_lines() swallow every exception and yield nothing, so a failing git diff reads as a clean pass; collect() does the same for an unreadable secret file. (published_digits() failing is the safe direction — nothing subtracted — and stays.) (c) With no raw exports present the script returns 0 silently, so the CI private-leak job, which can never hold the exports, reads as a pass while checking nothing. (d) The checker has no test, and its own docstring records that it once passed its planted figure. Plan. --message-file <path> mode (comment lines stripped), installed by install_git_hooks.sh as a commit-msg hook beside pre-commit; --audit additionally scans git log --format=%B. Inspection errors propagate → exit 2 with could not inspect: …. No reference data → print SKIPPED: no reference data on this machine; nothing was checked (exit 0), distinct from clean: …. ROOT / secret globs overridable so a script-style test beside test_tier_guard.py can build a scratch git repo with synthetic secrets. Done-when (§4): that test asserts exit codes exactly — planted figure staged → 1; planted figure in the message → 1; a truncated spelling of it → 1; clean → 0 with clean:; no reference data → 0 with SKIPPED; broken git → 2 — plus the pre-change control (the pinned pre-change script passes the message plant and the broken-git case); the CI private-leak job runs the same test, which becomes the one part of that job that tests something on a runner; --audit on this clone still reports clean (the count of figures printed, never a figure). Operator step after it lands: re-run scripts/testing/install_git_hooks.sh once — .git/hooks is untracked and not agent-writable (dashboard Waiting-on-you). What stays unfixed, deliberately: matching needs ≥ 8 significant digits; a figure rounded to 3–4 digits in prose, or transformed into a ratio or percentage, is invisible to any digit matcher that is not also drowning in false positives. The hook is a copy-paste net; the written rule remains the control. Closed 2026-09-22 — all eight exit-code cases plus the pre-change controls assert exactly, 24/24 (20260922T040113Z_OPS-58.log, 3 s, smoke host-side). --audit on this clone reported one match (2026-09-21); the operator ruled it a false positive — a shared geometric input the repo already publishes in plain text in its own SPEC.md, echoed back by the export, not an AED result — so no history rewrite. A narrow shared-input allowlist now suppresses exactly that site: an entry keys on (tracked path, JSON key present on the line, exact value) and carries its reason plus the tracked public source that publishes it; the value is computed from its published closed form, never written out, so an AED output cannot be entered at all. Suppression is never silent — the count and the site are printed on every run. Negative controls gate it: a synthetic AED output beside the allowlisted site is still flagged, and the same value in a different file, or under a different key in the same file, is still flagged. --audit now clean: with 1 shared-input match suppressed (20260922T040116Z_OPS-58-audit.log, 8 s). Operator step still open: re-run scripts/testing/install_git_hooks.sh once.
