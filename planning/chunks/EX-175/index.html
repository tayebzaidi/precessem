    EX-175 — refresh the stale example artifacts, in batches, on main¶

    History file for the §7 EX-175 row (OPS-46). Opened by the 2026-11-02 10:30 daily review; for the weekly to ratify, since EX-22 and EX-30 were weekly commissions. Lane 1's kind of work: a closing window on the current tree for rows whose last window is old.

    Why. The docrefs checker reports stale=208 (20261102T124159Z_EX-174-docrefs.log:248): artifacts of 109 examples older than its 336 h limit, the oldest ≈ 1 010 h, each line saying "rerun the example that writes it". Reviews have recorded the exit 2 and moved on. What the count hides is that those examples have not run against main for up to six weeks, while the package has moved under them. A re-run is the only test that they still pass their own imported gates. It needs no new target: the anchor is each example's own assertions.

    Done-when. Each batch's windows exit 0 with no script, guide, gate or band edited; each batch's named artifacts leave the stale list; a red or a kill is filed in known-issues and nothing is fixed in passing. EX-175 closes when the four batches below have landed. The remaining stale set goes to the weekly with its count.

    The common brief (items 762, 763, 764, 766).

    Windows. One harness call per example, bare, in the example's own documented form, labelled EX-175-<group><n>: scripts/testing/run_and_log.sh EX-175-imp1 "./scripts/run_examples.sh -e imp:1 -n 2 -t 180". Then one docrefs window for the batch: scripts/testing/run_and_log.sh EX-175-b<k>-docrefs "timeout -k 30 60 python3 scripts/testing/check_example_doc_references.py".

    Anchor. Each window's Status 0 and the example's own closing assertion line, read in the log. The imported gates are the example's and nothing is restated.

    Negative control. The artifact moved. Each batch's stems are in 20261102T124159Z_EX-174-docrefs.log and must be absent from the batch's docrefs window. Compare by name, not by count: artifacts age into the list by wall clock while a window runs, which is the whole of the 203 → 208 rise (EX-174's audit). A Status 0 with the stem still stale means the window did not write what the guide cites, and that is a finding.

    After each window. git status --porcelain shows only logs and test-results.md. A tracked file that a run rewrites is a finding: name it, and restore nothing silently.

    Tier, ranks. Each example's own -n and -t, listed below, unchanged. FEM_EM_SETUP_FIGURES stays unset. Pre-check pgrep -c python3 reads 0. Skip the slot if uptime loadavg (1 min) reads ≥ 16.

    Executor. The implementer directly: there is no script to write.

    Class. Example. The class median understates these: a batch is several windows, and each should run ≈ 10–25 min. The floor counts the median as the protocol says.

    Timebox. A slot starts no new window after minute 45. Windows not run stay listed in the item's outcome, and the item lands partial.

    Traps already paid for. Never edit an example to get green. No window above ≈ 600 s container-side; every -t below is at or under it. Foreground only, Bash timeout 660000 ms. A kill keeps its log, and a size kill is a finding, never raised. A leak-guard hit: the log moves unchanged to logs/leak-held/; these are not the ans: group, so one would be a surprise worth naming. Count verdicts per rank by token. mat:, imp: and th: run complex under run_examples.sh (EX-173's audit). A digit in a guide may differ from a new log at round-off: that is not a red, and the guide is not edited.

    Scope. A re-run. Not claimed: a re-closure of any EX-* chunk, any guide digit, or any new capability.

    Negative result. A red or a kill: stop the batch, keep the log, file a known-issues entry naming the example, the window and the first failing assertion, and mark the item BLOCKED with what ran. That is the item's most useful outcome. No PREDICTED RED: line.

    Status it can move. EX-175 progress, then ✅; a new known-issues entry per red.
