# OPS-62 — The `ANS-4` ladder's refinement guard counts unknowns, not cells

 **The `ANS-4` ladder's refinement guard counts unknowns, not cells** — opened and executed 2026-09-22 (interactive session, operator-instructed, **out of band**: it was not queued through §9, and §9 was deliberately left untouched). **Defect:** `tests/validation/test_ans4_resolution_ladder.py::test_every_finer_rung_actually_refines` asserted `finer["cells"] > coarser["cells"]` between consecutive rungs. That is the wrong invariant for step 2d's `h:degree` ladder, which refines in **h and p**: a p-rung holds the mesh fixed on purpose. **Evidence:** the 2026-09-22 XL window (`20260922T070007Z_ANS-4-step3e.log`, Status 1) ran the pre-registered `FEM_EM_ANS4_STEP2_RUNGSPEC="0.015:1 0.015:2 0.0075:2 0.005:2"` at 64 MHz; rungs 1 and 2 are the same mesh at degree 1 then degree 2, so the guard read `resolution 0.015 gave 116085 cells, not more than 0.015's 116085` (`:8802–8805, 8812`) while the discretisation actually went ≈139 302 → ≈742 944 unknowns (`:2452, 4542`). All four rungs completed and produced Z/S; the `PORT-11` gates, the record-rung check and the readout all passed — one spurious red on an otherwise usable window. **Internal inconsistency, not a judgement call:** the same file's stop rule is already stated in unknowns (`STOP_ABOVE_DOFS`, "cells mean different things at different orders"), through `_estimated_dofs(cells, degree)`; only the guard was never updated when the ladder gained p-rungs. **Fix:** `_refinement_measure(rung)` = `_estimated_dofs(rung["cells"], rung["degree"])` (the rung dicts have carried `degree` since `_four_port_rung` gained it) and a pure `_check_refines(rungs)` returning the offending consecutive pairs; the guard asserts that list is empty. **Strictly stronger, not loosened** — no tolerance, no `>=`, no equal-cells exemption: an inert `h` keyword still gives identical meshes at fixed degree ⇒ identical unknowns ⇒ still caught, **and** an inert or backwards `degree` knob, which a cell count cannot see, is caught too. Cells stay in the printed `[ANS-4 step2] refinement:` line (now cells *and* unknowns, rank 0 only); the failure message names the rung pair, both degrees and both unknown counts. **Controls (§4, smoke, `-n 2`, complex, `20260922T165511Z_OPS-62.log`, Status 0, 7 s):** `test_refinement_check_controls`, 1 passed in 1.3 s on **both** ranks, on synthetic rung dicts, no solve — four identical rungs ⇒ 3 failures caught; a p-rung (116 085 cells, degree 1 → 2) ⇒ clean, with the measure asserted at exactly 139 302 → 742 944; an h-rung ⇒ clean; **the real 3e ladder shape with that window's measured cell counts (116 085 / 116 085 / 281 728 / 592 744) ⇒ clean**, i.e. the fix would have let that window through; a degree drop at fixed h ⇒ caught; equal unknowns across a pair (1 600×1.2 == 300×6.4) ⇒ caught; and the strength case — cells 100 000 → 200 000 with degree 2 → 1, which the **old** cell guard passed and the new one catches. The module still collects: 6 tests in 2.5 s.
