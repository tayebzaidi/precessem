# OPS-56 — Sweep-planner endpoint inclusion must not depend on the carrier frequency

 **Sweep-planner endpoint inclusion must not depend on the carrier frequency** — opened 2026-09-19 (interactive session, from an external code review; reproduced in plain numpy with the function's own logic). `ports/sweep.py::_uniform_frequency_grid` decides whether to append the requested endpoint with a default `np.isclose`, whose `rtol = 1e-5` scales with the absolute frequency: at 128 MHz anything within ≈1.3 kHz of `stop_hz` (640 Hz at 64 MHz) counts as already present. Reproduced: `(127.7000e6, 127.7009e6, 500)` ends at 127.7005 MHz; `(127.7000e6, 127.7012e6, 1e3)` drops the endpoint; `(64.0000e6, 64.0005e6, 1e3)` returns a **single point**. kHz steps around a resonance are what `refined_step_hz` exists for and what birdcage tuning will ask of it; `tests/ports/test_frequency_sweep_planner.py` uses MHz spacing only, so nothing sees it. Two neighbours in the same function: non-finite inputs fail by accident (`nan` → `ValueError: cannot convert float NaN to integer`, `inf` → `OverflowError`), and `plan_frequency_sweep` de-duplicates the merged coarse+refined grid with `np.unique`, which merges only bitwise-equal floats — two points 1e-8 Hz apart both survive, and each is a full field solve. **Plan.** Validate start / stop / step finite (intended `ValueError`s). Decide inclusion from the grid's own construction: `n = floor(span/step + 1e-9)`; the endpoint is on-grid iff `abs(span − n·step) <= 1e-9·step`, in which case the last point is set to `stop_hz` **exactly**, otherwise `stop_hz` is appended. De-duplicate the merged grid with the same step-relative tolerance (the finest step in play) instead of `np.unique`. Tolerances are relative to the **step**, never to the carrier. **Done-when (§4):** unit tests asserting exact grids for the three reproduced cases (endpoint present, length as computed by hand), a nondivisible span, the float-noise case `(0.1, 0.3, 0.1)` → 3 points, an on-grid endpoint bitwise equal to `stop_hz`, a coarse/refined near-duplicate merging to one point, and the intended `ValueError` for each non-finite input; a pre-change control showing the three reproduced cases fail on the pinned pre-change sha; the two existing planner tests green unchanged.
