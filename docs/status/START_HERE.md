# Start here — orientation for a cold-start agent

**Read this file, then read only what your task needs.** The project's records
are large on purpose (every claim carries its evidence) and no agent can or
should ingest them whole: PROJECT_PLAN.md alone is ≈660 KB, about a full
context window. Paging through it costs tokens and, worse, silently misses the
paragraph that mattered. Grep for a chunk ID; read the row and the span it
points to; stop.

This file holds **no status of its own**. The state table lives in the
dashboard, the chunk list below is generated from PROJECT_PLAN.md §7, and
everything else is a pointer. If something here disagrees with the plan, the
plan is right and this file is stale — say so.

## 1. What is true right now — one table, maintained daily

`docs/status/dashboard.md` → **"Honest current state"** (≈ 15 rows: capability,
state, the gate that licenses it, and what is *not* claimed). It is a digest of
PROJECT_PLAN.md §2, rewritten by every daily review. Read it before trusting
any S-parameter, coil-loading or SAR figure. For the full wording of a claim,
grep its chunk ID in §2.1 (validated, with the number) or §2.2 (not validated —
do not trust, do not extend).

## 2. What to read for which job

| You are about to… | Read | Do not read |
|---|---|---|
| execute a queued item (implementer slot) | your protocol (`docs/automation/implementer-run.md`), then **§9 "On deck"** top open item, then that chunk's §7 row (grep its ID) and its `docs/planning/chunks/<ID>.md` if the row points there | the rest of §7, §10, the archives |
| debug a failing test | `docs/testing/known-issues.md` **first** (open entries only, ≈220 KB — grep the test id). Retired entries: `known-issues-archive.md` | — |
| check what happened recently | `git log`, then the last few `## <timestamp>` entries of `docs/testing/attempts.md` (7-day window) | `attempts-archive.md` unless chasing a parked branch |
| check a number or a log claim | the harness log under `docs/testing/logs/` named in the row; `docs/testing/test-results.md` is the index (grep the chunk ID) | — |
| plan or rescope | §6 phase map (13 KB), §10's live chains and newest assessment, `docs/status/weekly-progress.md` | superseded assessments (in `docs/planning/plan-archive.md`) |
| derive formulation / ports / BC theory | `docs/references/jin-fem-3e/INDEX.md` (operator-provided, may be absent) | — |
| touch an Ansys benchmark | CLAUDE.md hard rule on private numbers, then `examples/ansys_benchmarks/<case>/SPEC.md` | never copy from `aed_results/`, `COMPARISON_private.md`, `docs/private/` |

Need a fact with a citation and don't know where it lives? Ask the
`plan-navigator` agent — it searches the plan, known-issues, attempts,
test-results and all their archives and answers with `file:line` or NOT FOUND.
